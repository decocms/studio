## Como funciona o controle de acesso

O deco Studio ajuda você a gerenciar quem pode fazer o quê na sua organização. Pense nisso como gerenciar o acesso a um Google Drive compartilhado ou a uma organização no Slack — você decide quem está no seu time e o que cada pessoa pode fazer.

Existem duas formas principais de controlar o acesso:

- **Papéis dos membros do time** — O que as pessoas da sua organização podem fazer (visualizar, editar, gerenciar configurações, etc.)
- **Permissões de API keys** — O que sistemas automatizados ou ferramentas externas podem fazer quando se conectam à sua organização

## Papéis do time

Quando você cria uma organização, automaticamente recebe três papéis para atribuir aos membros do time:

- **Owner**: Controle total sobre tudo, incluindo excluir a organização ou remover membros do time
- **Admin**: Pode gerenciar operações do dia a dia, como adicionar conexões, criar agentes e convidar usuários
- **Member**: Acesso básico para visualizar e usar conexões existentes (ótimo para membros do time que só precisam trabalhar com o que já está configurado)

### Criando papéis personalizados

Precisa de algo mais específico? Você pode criar papéis personalizados de acordo com as necessidades do seu time.

**Exemplo**: Crie um papel "Developer" que pode gerenciar conexões e agentes, mas não pode excluir nada, ou um papel "Viewer" que só pode ver o que está configurado sem fazer alterações.

Para criar um papel personalizado:

1. Vá até **Members** na sua organização
2. Clique em **Manage Roles**
3. Clique em **Create Role**
4. Dê um nome a ele (como "Developer" ou "Support Team")
5. Selecione quais ações esse papel deve ter permissão para realizar

<Callout type="tip">
  **Dica**: Comece com a menor quantidade de acesso necessária e adicione mais permissões conforme for preciso. É mais fácil conceder mais acesso depois do que lidar com alterações ou exclusões acidentais.
</Callout>

## Permissões de API keys

As API keys permitem que ferramentas externas ou sistemas automatizados acessem sua organização sem exigir que alguém faça login. Quando você cria uma API key, você escolhe exatamente o que ela tem permissão para fazer.

**Exemplos de casos de uso**:
- Um sistema de monitoramento que só precisa ler o status das conexões
- Um script de deploy que precisa criar novas conexões
- Uma integração de terceiros que só deve acessar agentes específicos

**Boa prática**: Dê a cada API key apenas as permissões de que ela realmente precisa. Se um script apenas lê dados, não dê a ele permissão para excluir coisas.

## Onde gerenciar o acesso

Você vai trabalhar com essas configurações em alguns lugares diferentes:

- **Página Members**: Convide colegas de time, atribua papéis e crie papéis personalizados
- **API Keys**: Gerenciadas via ferramentas de MCP management ou pela API (veja [API Keys](/pt-br/studio/api-keys))
- **Página Agents**: Controle quais ferramentas e conexões cada agente pode acessar (útil para limitar o que assistentes de IA ou automações podem fazer)

## Exemplos práticos

### Dar acesso de admin a um membro do time

**Quando**: Você quer que alguém ajude a gerenciar conexões e convidar novos membros do time

1. Vá até **Members**
2. Encontre o nome da pessoa
3. Clique no papel atual dela (provavelmente "Member")
4. Selecione **Admin**

### Criar uma API key para uma ferramenta de monitoramento

**Quando**: Você tem um sistema que precisa verificar se suas conexões estão funcionando

Use as ferramentas de MCP management ou a API para criar uma key com permissões somente leitura para conexões. Veja [API Keys](/pt-br/studio/api-keys) para detalhes sobre como criar keys com permissões escopadas.

### Configurar um papel "Read-Only Analyst"

**Quando**: Você tem membros do time que precisam ver as configurações, mas não devem alterar nada

1. Vá até **Members** → **Manage Roles**
2. Clique em **Create Role**
3. Nomeie como "Read-Only Analyst"
4. Selecione apenas permissões de visualização (sem criar, atualizar ou excluir)
5. Atribua esse papel aos membros do time apropriados
