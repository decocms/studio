## Visão geral

O Decopilot fornece tools integradas que estão sempre disponíveis (sujeitas a restrições de task/subtask). Essas tools permitem gerenciamento de trabalho, acesso ao contexto e coordenação de agentes.

## Categorias de tools

### Descoberta e ativação

- [**enable_tool**](/pt-br/studio/api-reference/built-in-tools/enable-tool) — Ativa uma ou mais tools do escopo para que possam ser chamadas em etapas subsequentes

### Gerenciamento de tasks

- [**subtask**](/pt-br/studio/api-reference/built-in-tools/subtask-run) — Inicia uma subtask com contexto isolado, opcionalmente vinculada a um agente específico

### Interação com o usuário

- [**user_ask**](/pt-br/studio/api-reference/built-in-tools/user-ask) — Faz uma pergunta ao usuário quando uma entrada ou esclarecimento for necessário

### Acesso ao contexto

- [**read_resource**](/pt-br/studio/api-reference/built-in-tools/resource-read) — Lê documentação ou diretrizes do escopo atual
- [**read_prompt**](/pt-br/studio/api-reference/built-in-tools/prompt-read) — Lê um template de prompt reutilizável

### Trabalhando com a saída de tools

- [**read_tool_output**](/pt-br/studio/api-reference/built-in-tools/read-tool-output) — Relê um resultado grande de tool que foi descarregado para o armazenamento

### Pesquisa e mídia

Essas tools são registradas condicionalmente com base nos modelos padrão configurados pela organização:

- **web_search** — Executa um passo de pesquisa web aprofundada em streaming (requer um modelo de web-research)
- **generate_image** — Gera uma imagem (requer um modelo de imagem)

### Planejamento

- [**propose_plan**](/pt-br/studio/api-reference/built-in-tools/propose-plan) — Propõe um plano para aprovação. Registrada apenas quando o modo de chat é `plan`.

### Tools de sandbox (VM)

Quando um agente é suportado por uma sandbox (um repositório do GitHub vinculado), o decopilot também expõe seis tools de VM — `bash`, `read`, `write`, `edit`, `grep`, `glob` — que operam dentro dessa sandbox. Elas são provisionadas de forma preguiçosa no primeiro uso.

## Matriz de disponibilidade

| Tool | Task | Subtask | Notas |
|------|:----:|:-------:|-------|
| `enable_tool` | ✓ | ✓ | Ativa uma tool do escopo para a próxima etapa |
| `subtask` | ✓ | ✗ | Evita delegação infinita |
| `user_ask` | ✓ | ✗ | Subtasks não podem interromper o usuário |
| `read_resource` | ✓ | ✓ | |
| `read_prompt` | ✓ | ✓ | |
| `read_tool_output` | ✓ | ✓ | |
| `web_search` | ✓ | ✓ | Condicional ao modelo de web-research |
| `generate_image` | ✓ | ✓ | Condicional ao modelo de imagem |
| `propose_plan` | ✓ | ✗ | Apenas no modo plan |
| Tools de VM (`bash`, `read`, `write`, `edit`, `grep`, `glob`) | ✓ | ✓ | Apenas quando o agente possui uma sandbox |

<Callout type="info">
  **Tasks** são iniciadas pelo usuário e têm acesso total a todas as tools integradas. **Subtasks** são iniciadas pelo decopilot e têm acesso restrito para evitar delegação infinita e bloqueio de interações com o usuário. Subtasks têm um limite de 15 etapas (vs. 30 para tasks) e precisam retornar um resumo.
</Callout>

<Callout type="tip">
  **Descoberta de tools**: As tools de escopo disponíveis vindas de servidores MCP conectados são descobertas implicitamente por meio das conexões listadas no Virtual MCP do escopo atual — não existe uma tool de busca explícita. Use `enable_tool` para ativar uma tool antes de chamá-la.
</Callout>
