## 1) Executar o deco Studio

Escolha o tier que se encaixa. O Studio precisa de **PostgreSQL** e de um
**object store compatível com S3**; o **NATS** já vem no chart; a **sandbox**
(code-execution + previews) é uma camada opcional. A pasta [`selfhost/`](https://github.com/decocms/studio/tree/main/selfhost)
do repositório tem scripts prontos, values de exemplo e o mapa completo de dependências.

| Tier | Como | Dependências |
|------|------|--------------|
| **Local — CLI** | `bunx decocms` | embutido, na sua máquina |
| **Local — Compose** | `docker compose -f deploy/docker-compose/docker-compose.postgres.yml up` | tudo embutido (Postgres + NATS + MinIO) |
| **Local — Kubernetes** | um `helm install` do umbrella `selfhost/examples/k8s-local` | tudo embutido (Postgres + MinIO de dev + NATS + sandbox) |
| **Produção — Kubernetes** | `helm install` [o chart](/pt-br/studio/self-hosting/deploy/kubernetes) | Postgres + S3 + NATS + ClickHouse externos/gerenciados |

<Callout type="tip">
  **Prefere uma instalação guiada?** O **guia de self-host para agentes de código** ([`SKILL.md`](https://github.com/decocms/studio/blob/main/selfhost/skills/self-host-studio/SKILL.md)) entrevista você — dependências gerenciadas ou no cluster, secrets, sandbox — e escreve um diretório de instalação que fica com você: um umbrella chart com dependências OCI fixadas mais os seus values, validado com `helm template` antes de aplicar qualquer coisa. O mesmo diretório instala num cluster local e num gerenciado, e não envolve clonar este repositório. É markdown puro, então aponte qualquer agente de código para ele; no Claude Code dá para instalar como skill:
</Callout>

Adicione uma vez (o repositório é público) e diga ao Claude Code **"install Studio"**:

```bash
curl -fsSL https://raw.githubusercontent.com/decocms/studio/main/selfhost/skills/install.sh | sh
```

### Opção A: local com um comando (CLI)

```bash
bunx decocms
```

Instância local com PostgreSQL embutido — totalmente privada. O pacote é
publicado como `decocms`; o binário chama-se `deco`.

### Opção B: Docker Compose (tudo embutido)

Sobe Studio + PostgreSQL + NATS + MinIO como containers, tudo cabeado — sem
serviços externos. Imagens multi-arch (roda nativo no Apple Silicon).

```bash
git clone https://github.com/decocms/studio.git
cd studio
docker compose -f deploy/docker-compose/docker-compose.postgres.yml up
open http://localhost:3000     # signup — primeiro usuário vira owner
```

Sobrescreva os defaults de dev (secrets, credenciais) via um `.env` ao lado do
compose. **Mais detalhes:** [Local: Docker Compose](/pt-br/studio/self-hosting/deploy/docker-compose)

### Opção C: executar a partir do código-fonte

```bash
git clone https://github.com/decocms/studio.git
cd studio
bun install
bun run dev
```

### Opção D: Kubernetes

O chart oficial (`deploy/helm/studio`) é **enxuto**: sobe Studio + NATS e espera
**Postgres, object storage (S3) e ClickHouse (opcional) externos**.

Para um **cluster local** (Rancher Desktop / kind / minikube), um umbrella chart
(`selfhost/examples/k8s-local`) compõe o chart enxuto + a camada de sandbox como
dependências Helm e adiciona Postgres + MinIO descartáveis — então um único
`helm install` sobe a stack inteira, já ligada, incluindo o sandbox:

```bash
helm dependency build selfhost/examples/k8s-local
helm install deco-studio selfhost/examples/k8s-local -n deco-studio --create-namespace
kubectl -n deco-studio port-forward svc/deco-studio 8080:80   # → http://localhost:8080 (confiável em qualquer cluster)
# studio.localhost também funciona SE o LoadBalancer pegou a :80 — no Rancher Desktop stock o Traefik do k3s ocupa a :80, então use o port-forward
```

Use o release name `deco-studio`. O `./selfhost/scripts/local-k8s.sh` encapsula
isso (com espera de rollout e `uninstall`).

Em **produção**, aponte o chart para serviços gerenciados e use external secrets
+ autoscaling. Veja [Kubernetes: Helm Chart](/pt-br/studio/self-hosting/deploy/kubernetes).

<Callout type="tip">
  O quadro completo — tiers, o modelo batteries-included vs. dependências
  destacáveis, a sandbox (egress lockdown + previews), runtimes locais de
  Kubernetes e o posture de produção — está em [`selfhost/README.md`](https://github.com/decocms/studio/tree/main/selfhost).
</Callout>

## 2) Criar uma Connection

Ao abrir uma nova organização, o deco Studio vai solicitar que você:

- **Navegue pela Store** ou
- **Crie uma Connection** diretamente - forneça a URL do MCP (endpoint HTTP) e quaisquer credenciais necessárias

A **Store** é um catálogo de Connections às quais você pode se conectar. Por padrão, a Store aponta para o **MCP Registry oficial**.

## 3) Criar uma organização e convidar membros

- Vá para **Members**
- Convide colegas de equipe
- Atribua roles (Admin/User) conforme necessário

## 4) Criar um Agent (servidor virtual)

- Vá para **Agents**
- Clique em **Create Agent**
- Escolha **Include** (apenas connections/tools selecionadas) ou **Exclude** (tudo exceto as exclusões)

## 5) Gerar uma API key para um client

Crie uma API key com as permissões mínimas de tools necessárias (veja [API Keys](/pt-br/studio/api-keys)).

## 6) Verificar monitoramento

Use o **Monitoring** para confirmar:

- invocações de tools estão sendo registradas
- latência + taxas de erro aparecem
- filtros (intervalo de tempo, nome da tool, connection, agent) funcionam como esperado

<Callout type="tip">
  O teste de fumaça mais rápido é chamar uma tool através de um endpoint de agent (assim você exercita agregação + proxy + monitoring).
</Callout>
