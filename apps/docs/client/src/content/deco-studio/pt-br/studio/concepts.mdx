## Como o Studio é organizado

O Studio usa um pequeno conjunto de conceitos que se constroem uns sobre os outros. Depois que você entende esses, todo o resto vem por consequência.

- **Organization** — seu workspace de nível mais alto. Tudo pertence a uma org: members, agents, connections, automations e logs.
- **Agent** — uma IA configurada para um trabalho específico: um conjunto focado de tools, instruções claras e um propósito restrito. Agents são a superfície de trabalho do Studio. Veja [Agents](/pt-br/studio/agents).
- **Connection** — uma tool ou serviço que você plugou (GitHub, Slack, um banco de dados, sua própria API). As credenciais são armazenadas uma vez e compartilhadas com segurança. Veja [Connections](/pt-br/studio/connections).
- **Thread** — uma sessão de conversa dentro de um agent. O Studio salva o histórico para você poder voltar a um trabalho em andamento.
- **Automation** — uma execução de agent que dispara em um schedule ou em resposta a um evento. Veja [Automations](/pt-br/studio/automations).
- **AI Provider** — um modelo de IA configurado (Anthropic, Google, OpenRouter ou o Deco AI Gateway) que alimenta seus agents e o Decopilot. Veja [AI Providers](/pt-br/studio/ai-providers).
- **Member** — uma pessoa na sua organização com um role e permissões.

## Anatomia da UI do Studio

### Home e a sidebar

Quando você abre o Studio, cai na **tela inicial**: um único campo de chat — _"What's on your mind?"_ — alimentado pelo **Decopilot**, o assistente nativo do Studio, além de um grid customizável de atalhos para seus agents. É só começar a digitar para iniciar; a conversa que você começa fica salva em **Decopilot** na sidebar.

A sidebar fixa à esquerda é a mesma em qualquer lugar que você vá:

- **Home** — o campo de chat da tela inicial.
- **Library** — um navegador de arquivos para o filesystem compartilhado da sua organização. Veja [Library](/pt-br/studio/library).
- **Threads** — suas conversas recentes, agrupadas por agent (as do Decopilot ficam em "Decopilot"). Clique em uma para retomá-la; comece uma nova pela Home ou pelo botão **+** / "Browse agents".
- **Settings** — abre a partir da parte de baixo da sidebar; tudo que não está atrelado a um único agent.

### O workspace do agent

Abra um agent — ou inicie uma thread com ele — e a tela se divide em duas:

- **Esquerda — chat.** Converse com o agent em linguagem natural; ele usa as tools anexadas para fazer o trabalho. As mensagens anteriores ficam aqui. Acima do campo de entrada fica o **model picker**.
- **Direita — um painel com abas.** Quais abas aparecem depende do agent:
  - **Settings** — instruções, connections anexadas, files & skills (exibido se você pode gerenciar agents)
  - **Automations** — schedules e gatilhos de eventos (sempre disponível)
  - **Preview** — um preview ao vivo, para agents baseados em um repo ou site
  - **Content** — edite páginas e seções, para agents baseados em conteúdo
  - **Review changes** — review de branch e PR, para agents Git-native com um pull request aberto

Tudo que você precisa para usar, configurar e monitorar um único agent fica nessa mesma tela. Veja [Agents](/pt-br/studio/agents) para o detalhamento completo.

### Settings

Tudo que não está atrelado a um único agent fica em **Settings**. Abra a partir do canto inferior esquerdo da sidebar. Lá dentro você encontra:

- **Organization** — General, Brand Context, AI Providers, Secrets, Buckets
- **Build** — Connections, Agents (o catálogo), Automations, Store
- **Manage** — Monitor, Members, Roles, Security (SSO)
- **Extensions** — Plugins
- **Account** — Profile & Preferences

Quando outras páginas destes docs dizem "vá em Connections" ou "abra o Monitor", elas se referem a essas seções de Settings.

## Como o protocolo funciona

O deco Studio é construído sobre o [Model Context Protocol](https://modelcontextprotocol.io/) (MCP), um padrão aberto para conectar clients de IA a tools e serviços. Você não precisa entender o MCP para usar o Studio, mas conhecer os três blocos de construção ajuda:

- **Tools** — ações que uma IA pode executar (buscar em um banco de dados, enviar um email, criar um arquivo)
- **Resources** — fontes de dados somente leitura que dão contexto a uma IA (documentos, configs, dados da org)
- **Prompts** — templates reutilizáveis para workflows comuns, com variáveis que você pode preencher

O Studio fica entre seus clients de IA (como Claude Desktop ou Cursor) e suas tools, cuidando de autenticação, roteamento e logging para cada requisição.

## Como uma requisição flui pelo Studio

Quando um agent chama uma tool, eis o que acontece:

```
┌─────────┐                    ┌──────────────┐                  ┌────────────┐
│ Client  │ ──[authenticate]──▶│  deco Studio │ ──[with creds]──▶│ MCP Server │
│ (Cursor)│                    │              │                  │  (GitHub)  │
└─────────┘ ◀──[response]──────└──────────────┘ ◀─[response]─────└────────────┘
                                      │
                                      └──▶ [audit log]
```

1. O client se autentica no Studio
2. O Studio verifica se o client tem permissão para usar a tool solicitada
3. O Studio recupera as credenciais armazenadas para aquela connection
4. O Studio encaminha a requisição para o serviço upstream
5. O Studio registra a invocação — tool, timing, inputs, outputs e quem chamou
6. O Studio retorna a resposta para o client

As credenciais nunca saem do Studio, toda ação é registrada e o acesso é consistente independentemente de qual client fez a requisição.

## Por que o monitoramento é nativo

Sem um control plane, cada client gerencia seus próprios logs — ou não registra nada. O Studio registra cada chamada de tool que passa pela plataforma, criando um único lugar para debugar falhas, acompanhar performance e auditar quem acessou o quê. Sem configuração extra. Veja [Monitoring](/pt-br/studio/monitoring).
