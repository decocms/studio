## O que é uma automation?

Uma **automation** é uma execução de agent que acontece sozinha — em um schedule, ou quando algo ocorre em um serviço conectado. Ninguém precisa estar observando. O agent executa, faz seu trabalho, e o resultado aparece no [Monitoring](/pt-br/studio/monitoring).

Toda automation pertence a um [agent](/pt-br/studio/agents) específico. Ela executa *aquele* agent com *as* tools dele — a automation apenas decide quando disparar e com qual prompt começar.

Cada automation tem:

- **Um agent** — o que faz o trabalho
- **Um prompt** — o que ele deve fazer a cada execução
- **Um model** — qual AI provider e credenciais usar
- **Um trigger** — quando dispara (schedule, evento ou webhook)

<Callout type="warning">
  Automations aprovam todas as chamadas de tool automaticamente — não há etapa de revisão humana. Anexe apenas as tools que o agent realmente precisa, para que ele não possa fazer mais do que você pretende.
</Callout>

## Onde elas vivem

Você gerencia automations em dois lugares:

- **Dentro de um agent** — abra o agent e clique na aba **Automations**. Você verá as automations anexadas a este agent específico, e pode criar novas em contexto.
- **Settings → Automations** — a lista, em toda a org, de cada automation de cada agent, útil para visão geral, auditoria ou organização.

## Quando usar automations

- **Tarefas agendadas** — relatórios diários, sincronizações de dados, jobs de limpeza
- **Fluxos orientados a eventos** — novo pedido → iniciar fulfillment, novo ticket → triagem, deploy → enviar notificação
- **Qualquer coisa que deva rodar sem alguém disparando manualmente**

Se você quer um humano no loop — revisando ações antes de acontecerem — abra o agent e converse com ele diretamente, ou use o [Decopilot](/pt-br/studio/decopilot/overview). Automations são para trabalho que você já validou e quer rodar hands-free.

## Criando uma automation

1. Abra o agent que você quer executar
2. Clique na aba **Automations**
3. Clique em **New automation**
4. Escreva o prompt — o que o agent deve fazer a cada execução?
5. Escolha um model e credenciais
6. Adicione um trigger (schedule, evento ou webhook)
7. Ative-a

## Triggers

### Schedule

Executa a automation em um schedule recorrente. Os horários são em UTC.

| Expressão | Quando executa |
|---|---|
| `0 9 * * *` | Todo dia às 9:00 |
| `0 */6 * * *` | A cada 6 horas |
| `0 9 * * 1` | Toda segunda-feira às 9:00 |
| `*/5 * * * *` | A cada 5 minutos |

O intervalo mínimo é de 5 minutos — `*/5 * * * *` é o schedule mais apertado permitido. Se o sistema reiniciar, execuções perdidas são detectadas e disparadas no próximo ciclo.

### Event

Dispara quando um serviço conectado publica um evento correspondente. Você especifica a connection, o tipo de evento e filtros opcionais — apenas eventos que correspondem a todos os filtros disparam a automation.

### Webhook

Dispara quando um sistema externo envia uma requisição HTTP para uma URL dedicada. Quando você adiciona um trigger de webhook, o Studio gera uma URL de uso único e um token secreto (exibido uma vez) — faça POST nessa URL para executar a automation. Você pode fazer rotação do token caso ele seja exposto.

## Limites

- Máximo de 10 execuções de automation em toda a sua organização ao mesmo tempo
- Cada execução expira após 5 minutos
- Payloads de evento são limitados a 1 MB

Se a pessoa que criou uma automation sai da organização, ela é automaticamente desativada. O mesmo acontece quando uma execução encontra um erro irrecuperável — por exemplo, quando o model configurado para a automation deixa de ser permitido para o seu role após uma mudança de permissão — assim ela para de tentar de novo e falhar silenciosamente, mostrando um motivo claro de desativação em [Monitoring](/pt-br/studio/monitoring).
