## O que serão os Projects

Hoje o Studio tem dois níveis de hierarquia: **Organization → Agent**. Projects é um terceiro conceito planejado que vai ficar entre os dois — um workspace compartilhado que agrupa agents, connections e contexto em torno de um objetivo, cliente ou time específico.

Quando os Projects voltarem, você terá:

- **Agrupamento** — organize agents por linha de produto, cliente, time ou iniciativa
- **Connections e credenciais com escopo** — mantenha o trabalho de marcas ou clientes separados isolado
- **Instruções no nível do projeto** — diretrizes e contexto compartilhados que se aplicam a todo agent do projeto
- **Controle de acesso no nível do projeto** — dê a um time acesso a apenas um projeto sem expor o resto da org

Até lá, você pode aproximar os Projects marcando ou nomeando agents de forma consistente, e usando roles de membros no nível da org para controle de acesso.

## Por que estamos trazendo de volta

Usuários multi-marca e multi-time precisam de uma camada entre "tudo na org" e "este único agent". Uma lista plana de agents sob uma org funciona para configurações pequenas, mas deixa de escalar quando você tem clientes ou iniciativas separados que não deveriam se ver.

Removemos os Projects temporariamente para simplificar a UI enquanto os redesenhávamos. A nova versão vai se integrar de forma limpa com a superfície atual centrada em agents — seus agents existentes continuarão funcionando, e os Projects se tornarão uma forma opcional de agrupá-los.
