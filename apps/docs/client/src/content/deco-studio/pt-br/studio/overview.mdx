## A casa dos seus agentes de IA

O deco Studio é onde você constrói agents, conecta-os a tools, executa em schedules ou eventos e vê exatamente o que estão fazendo. Self-host ou use a cloud. Construído sobre o [Model Context Protocol](https://modelcontextprotocol.io).

### Agents

Um agent é uma IA configurada para um trabalho específico: um conjunto focado de tools, instruções claras e seu próprio histórico de thread. Agents são a superfície de trabalho do Studio — você passa a maior parte do tempo dentro de um. Cada agent também é seu próprio endpoint MCP, então clients externos como Cursor e Claude Desktop podem usá-lo diretamente.

### Connections

Plugue qualquer tool ou serviço — GitHub, Slack, bancos de dados, sua própria API, qualquer coisa compatível com MCP. Configure as credenciais uma vez no nível da org, depois anexe as tools que quiser a cada agent. As credenciais nunca saem do Studio.

### Automations

Execute um agent sem supervisão em um schedule ou em resposta a um evento. Anexado a um agent específico, então o escopo do que a execução pode fazer é o que você configurou para aquele agent.

### Observability

Cada chamada de tool feita pelos seus agents é registrada automaticamente — quem chamou, quando, o que retornou e quanto tempo levou. Um único lugar para debugar, auditar e acompanhar performance.

### Extensibilidade

O Studio é aberto em todas as camadas:

- **MCP apps** — empacote tools com views em React em um único pacote, e o Studio renderiza essas views diretamente dentro do agent. Comece pelo [template repo](https://github.com/decocms/mcp-app).
- **Sandboxes** — vincule um agent a um repositório do GitHub e o Studio o executa como um ambiente de dev isolado com escopo daquele agent (tipicamente o próprio MCP server do agent).
- **Git-native** — agents baseados em código vivem em um repo real com branches e PRs, exibidos na aba **Git** do agent. Seu controle de versão continua sendo sua fonte da verdade.
- **MCP em todos os lugares** — cada agent é exposto como seu próprio endpoint MCP, chamável a partir do Cursor, Claude Desktop, seu próprio código ou outro agent.

### Solutions: suítes de agents prontas

Para times que gerenciam storefronts e experiências digitais ricas em conteúdo, a deco oferece **suítes de agents empacotadas** construídas sobre o Studio — a mais completa disponível hoje é o **[Agentic CMS](./solutions/agentic-cms)**, a evolução do [deco.cx](https://docs.deco.cx). Veja [Solutions](./solutions/overview) para a lista completa.

### O que você pode fazer com o Studio

| | |
|---|---|
| **Construir agents** | Componha workers de IA focados a partir das suas tools conectadas, instruções e resources |
| **Conectar tools** | Adicione GitHub, Slack, bancos de dados ou qualquer MCP server — as credenciais ficam seguras |
| **Rodar hands-free** | Dispare agents em schedules ou eventos com automations |
| **Ver tudo** | Logs, custos e traces de cada ação de agent, em um único dashboard |
| **Estender com código** | Publique MCP apps (tools + UI) e vincule agents a repos Git em seus próprios sandboxes |
| **Controlar acesso** | Gerencie quem pode usar quais tools com roles e permissões de time |
| **Rodar do seu jeito** | Self-host na sua própria infraestrutura ou use nossa cloud |

### Opções de deployment

| | |
|---|---|
| **Local** | `bunx -p decocms deco` — roda inteiramente na sua máquina, totalmente privado |
| **Cloud** | [studio.decocms.com](https://studio.decocms.com) — gerencie tudo pelo navegador |
| **Team** | Connections, roles e tracking de custos compartilhados em toda a organização |
| **Self-hosted** | Faça deploy na sua própria infraestrutura com Docker ou Kubernetes |
