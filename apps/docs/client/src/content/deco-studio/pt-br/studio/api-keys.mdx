## O que são API Keys?

API keys permitem que sistemas externos se conectem ao deco Studio sem precisar que um usuário faça login. São tokens simples que você pode usar em scripts, ferramentas de automação ou qualquer sistema que precise acessar o deco Studio programaticamente.

<Callout type="warning">
  API keys são para **sistemas externos se conectando ao deco Studio**. Para conectar o deco Studio a servidores MCP upstream, veja [Conexões](/pt-br/studio/connections).
</Callout>

## Quando Usar API Keys vs OAuth

**OAuth** (Recomendado para a maioria dos usuários)
- Use com Cursor, Claude Desktop, VS Code
- Login pelo navegador
- Configuração mais fácil

**API Keys**
- Use para scripts e automação
- Sem necessidade de login no navegador
- Melhor para servidores e CI/CD

## Criando uma API Key

API keys são gerenciadas através das ferramentas MCP de gerenciamento ou da API. Ao criar uma API key, você especifica:

1. Um nome descritivo (como "Meu Script de Automação")
2. Um objeto `permissions` explícito — **obrigatório** (veja o formato abaixo)
3. **Copie a chave imediatamente** — ela só é exibida uma vez

<Callout type="warning">
  O campo `permissions` é **obrigatório**. Criar uma chave sem ele falhará com erro `400`.
</Callout>

### Formato das permissões

As permissões seguem a estrutura `{ recurso: [ações...] }`:

| Valor | Descrição |
|-------|----------|
| `{ "self": ["*"] }` | Acesso completo a todas as ferramentas de gerenciamento |
| `{ "conn_<UUID>": ["read"] }` | Acesso somente leitura a uma conexão específica |
| `{ "*": ["*"] }` | Curinga — acesso completo a tudo |
| `{ "self": ["LIST", "GET"] }` | Apenas as ações `LIST` e `GET` nas ferramentas de gerenciamento |

O recurso pode ser `"self"` para ferramentas de gerenciamento, `"conn_<UUID>"` para uma conexão específica, ou `"*"` para corresponder a todos os recursos.

<Callout type="warning">
  Uma API key é autorizada **estritamente pela sua lista de permissões (`permissions`)**. A função do proprietário não amplia o acesso de uma chave — uma chave pertencente a um admin, mas escopada para `AUTOMATION_LIST`, não pode chamar nenhuma outra ferramenta, mesmo as que o admin pode usar. Uma chave equivale exatamente à sua lista de permissões, nada mais.
</Callout>

<Callout type="error">
  Você só pode ver a API key uma vez. Armazene em um lugar seguro como um gerenciador de senhas.
</Callout>

## Usando Sua API Key

Adicione a API key na configuração do seu cliente MCP:

```json
{
  "mcpServers": {
    "deco": {
      "url": "https://studio.decocms.com/api/your-org-slug/mcp/gateway/your-agent-id",
      "transport": "http",
      "headers": {
        "Authorization": "Bearer mcp_key_abc123..."
      }
    }
  }
}
```

Substitua `your-org-slug` pelo slug da sua organização e `your-agent-id` pelo id do agent. Veja a referência [Connection Proxy](/pt-br/studio/api-reference/connection-proxy) para o esquema completo de paths.

## Boas Práticas de Segurança

<Callout type="warning">
  Trate API keys como senhas. Nunca compartilhe ou faça commit em repositórios de código.
</Callout>

**Conceda permissões mínimas**: Dê apenas o que é realmente necessário. As chaves são limitadas exatamente à sua lista de permissões — sem elevação implícita pelo papel (role) do proprietário da chave.

**Crie chaves separadas**: Use uma chave por ferramenta ou script — mais fácil de gerenciar se algo der errado.

**Armazene com segurança**: Mantenha chaves em um gerenciador de senhas ou gerenciador de segredos, nunca em arquivos de texto simples.

**Faça rotação regularmente**: Crie novas chaves a cada poucos meses e exclua as antigas.

**Monitore o uso**: Verifique o dashboard regularmente para atividades incomuns.

<Callout type="tip">
  Combine API keys com [Agentes](/pt-br/studio/agents) para controlar exatamente quais ferramentas seus scripts podem acessar.
</Callout>
