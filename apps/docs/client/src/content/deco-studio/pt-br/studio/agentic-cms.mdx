## O que é o Agentic CMS?

O **Agentic CMS** é a próxima geração do [deco.cx](https://docs.deco.cx) — um CMS visual para storefronts e experiências digitais ricas em conteúdo, construído sobre o [deco Studio](/pt-br/studio/overview). É o carro-chefe da [suíte Digital Experience](/pt-br/studio/digital-experience) da deco.

São duas coisas em uma:

- **Um CMS** — componentes React type-safe, loaders em TypeScript, theme editor, versionamento baseado em Git, colaboração em tempo real entre desenvolvedores e times de conteúdo. O mesmo modelo que o deco.cx estabeleceu, refinado.
- **Um time de agents** — workers de IA focados que produzem conteúdo, ajustam o design, enriquecem o catálogo e mantêm o site saudável. Eles trabalham junto com o seu time e você mantém o controle.

## Para quem é

Times que gerenciam **storefronts** (ecommerce, marketplaces) e **sites orientados a conteúdo** (mídia, D2C de marca, bases de conhecimento) que querem:

- A colaboração e a performance de uma stack code-first
- A velocidade e o alcance de um editor visual
- Agents de IA que escalam o trabalho operacional — sem esconder o que estão fazendo

Ele elimina a fronteira entre "o time de engenharia que mantém o site" e "o time de conteúdo que o preenche." Ambos trabalham no mesmo produto, com agents cuidando do trabalho repetitivo no meio do caminho.

## Git-native, por design

Toda mudança no seu site — seja feita por uma pessoa no editor visual ou por um agent a partir do chat — passa pelo mesmo workflow Git que você já conhece:

1. A mudança é commitada em uma branch
2. Um pull request é aberto com um diff que seu time pode revisar
3. Revisores aprovam ou pedem mudanças
4. No merge, a mudança vai para o seu site

Esse é o mesmo modelo que o deco.cx pioneirou, e ele se mantém diretamente. **Agents não pulam a revisão.** Eles abrem PRs como qualquer outra pessoa, e seu time continua sendo a fonte da verdade — seu repo, suas branches, seu histórico. Faça rollback, audite e rastreie qualquer mudança até seu autor, humano ou agent.

## Como se relaciona com o deco.cx

Se você está vindo do deco.cx, o Agentic CMS é a mesma linha de produto — os mesmos conceitos centrais (sections, loaders, blocks, theme editor, Decopilot), agora plugados no Studio para que seu storefront venha com um control plane de agents completo ao seu redor.

| conceito deco.cx | Agentic CMS hoje |
|---|---|
| Sections (componentes React/TS) | Iguais, com variantes opcionais geradas por agents |
| Loaders (busca de dados) | Iguais, agora visíveis como tools para seus agents |
| Blocks (unidades reutilizáveis) | Iguais |
| Theme Editor | Igual |
| Decopilot | Promovido a assistente de primeira classe com escopo no seu site |
| Admin UI | Agora parte do agent shell do Studio |
| Git workflow | Igual — toda mudança passa pela revisão de PR |

Projetos deco.cx existentes continuam funcionando. A migração adiciona a camada de agents; ela não substitui sua base de código.

## Sites em Blocks next-major

Sites construídos com Blocks next-major (v8) são editados pelo **protocolo de conteúdo**: o editor do site lê o schema commitado (`.deco/schema.gen.json`) e os blocos salvos em `.deco/blocks`, e nunca executa o código do site. O Studio só trata um site como v8 quando o schema declara `"blocksMajor": 8`, que o `deco schema` escreve; qualquer outro site continua no editor v7. Sites v8 mostram um pequeno selo **v8** no editor do site.

Um site usa o protocolo quando:

- **Você abre o link que o `deco serve` mostra.** Rode `npx @decocms/blocks serve` ao lado do seu servidor de desenvolvimento e abra o link `/site-editor` dele. Não precisa de conta no Studio: ele abre o app Site Editor, com as mesmas abas Preview e Content de dentro de um projeto, conectado ao servidor da sua máquina (com login, a barra lateral lista suas organizações). Publicação, releases e o backend do GitHub não estão lá. O Preview mostra o app indicado em `deco serve --preview` (`--preview localhost:8001`; por padrão, a porta do seu Vite), e o navegador lembra o servidor. Abrir `/site-editor` sem link procura esse servidor e a porta padrão (`localhost:4545`): se um responde, o editor abre; senão, a página mostra como iniciar o `deco serve` e abre o editor assim que ele responder. Se o servidor parar enquanto você edita, a página volta a esperar por ele. O Studio só aceita links para um servidor na sua máquina (`localhost`; links com `127.0.0.1` e `[::1]` abrem como `localhost`); o Chrome pergunta uma vez se o Studio pode acessá-lo.
- **Você cola esse link na opção de rascunho "Local" de um projeto.** Com login, abra o seletor de rascunhos, depois **Avançado → Local**, e cole o link do `deco serve`. O Studio confere se o servidor responde antes de trocar. Uma URL de túnel ali continua funcionando como antes, para sites v7. O editor mostra um chip **Servidor local** e reconecta sozinho quando o servidor reinicia; escolher um rascunho no seletor sai do Local.
- **A branch de uma sessão Fast Preview tem um schema commitado com `"blocksMajor": 8`**, atrás da flag de organização `site_editor_content_protocol` (desligada por padrão). Cada salvamento é um commit na branch de rascunho, o schema vem dessa branch (ou da branch padrão, quando ela não tem um) e o preview renderiza seu site com um link `?__draft=`.

Com o `deco serve`, os salvamentos escrevem os arquivos da sua working tree e os uploads vão para `public/assets/`, e você mesmo faz o commit.

Todo o resto, incluindo sessões com sandbox, continua no caminho de edição atual.

Como o código do site nunca roda:

- O preview abre o app de verdade; nada é re-renderizado no lugar, e a galeria de adicionar seção mostra o nome, a descrição e a imagem do schema de cada bloco.
- Seletores cujas opções vêm de um loader mostram as opções do schema, senão um campo de texto.
- Campos secretos são somente escrita: o Studio criptografa o que você digita no navegador com a chave pública do site, `.deco/secrets.pub`, e salva só o texto cifrado. Segredos salvos por sites mais antigos não podem ser editados aqui.
- Executar loaders e actions e instalar apps não está disponível: isso vive no código do site.

## Primeiros passos

Abra o Studio, encontre o agent **deco Site Editor** e aponte-o para o seu site.

  O Agentic CMS não é um produto separado — é uma configuração de Studio + o CMS do deco.cx, empacotada para times de storefront. Tudo o que você aprende sobre agents, connections e automations do Studio se aplica diretamente.
</Callout>
