## Visão geral

Lê um template de prompt do escopo atual. Suporta herança de escopo assim como os resources (project herda de org, agent herda de project+org). Templates de prompt fornecem instruções e workflows reutilizáveis.

## Disponibilidade

- **Tasks**: ✓ Disponível
- **Subtasks**: ✓ Disponível

## Assinatura

```typescript
prompt_read(
  prompt_name: string,
  options?: RangeOptions
)

type RangeOptions = {
  lineStart?: number
  lineEnd?: number
}
```

## Parâmetros

| Parâmetro | Tipo | Obrigatório | Descrição |
|-----------|------|----------|-------------|
| `prompt_name` | `string` | Obrigatório | Nome do template de prompt |
| `options` | `RangeOptions` | Opcional | Opções de intervalo de linhas |
| `options.lineStart` | `number` | Opcional | Número da linha inicial (padrão: 0) |
| `options.lineEnd` | `number` | Opcional | Número da linha final (padrão: 20) |

## Retorno

Conteúdo e metadados do template de prompt:
- **content**: O texto do template de prompt
- **name**: Nome do template de prompt
- **metadata**: Informações adicionais sobre o prompt

## Comportamento

- Suporta herança de escopo (igual ao `resource_read`):
  - Prompts de project herdam dos prompts da organization
  - Prompts de agent herdam dos prompts de project + organization
- Defina `options.lineStart` e `options.lineEnd` como 0 para ler o prompt inteiro
- O comportamento padrão (sem options) lê as primeiras 20 linhas (linhas 0-20)
- Números de linha são indexados a partir de zero

## Exemplos de uso

### Ler o prompt inteiro

```typescript
// Read entire code review prompt
prompt_read("code-review-workflow", { lineStart: 0, lineEnd: 0 })
```

### Ler linhas específicas

```typescript
// Read lines 5-15 of deployment prompt
prompt_read("deployment-steps", { lineStart: 5, lineEnd: 15 })
```

### Ler o início do prompt

```typescript
// Read first 20 lines (default)
prompt_read("bug-fix-workflow")
```

### Templates de workflow

```typescript
// Read feature development workflow
prompt_read("feature-workflow", { lineStart: 0, lineEnd: 0 })

// Read bug triage workflow
prompt_read("bug-triage", { lineStart: 0, lineEnd: 0 })

// Read code review checklist
prompt_read("review-checklist", { lineStart: 0, lineEnd: 0 })
```

## Casos de uso

### Execução de workflow

Siga workflows padronizados:

```typescript
// Read deployment workflow
const workflow = prompt_read("deploy-to-production", { lineStart: 0, lineEnd: 0 })

// Execute each step in the workflow
// ... workflow execution logic
```

### Reutilização de templates

Use templates de prompt para execução consistente de tarefas:

```typescript
// Read bug fix template
const template = prompt_read("bug-fix-template", { lineStart: 0, lineEnd: 0 })

// Apply template structure to current bug
// ... bug fix logic
```

### Instruções específicas de domínio

Acesse instruções especializadas:

```typescript
// Read security review prompt
const securityPrompt = prompt_read("security-review", { lineStart: 0, lineEnd: 0 })

// Perform security review using the prompt
// ... security review logic
```

## Herança de escopo

Prompts seguem a hierarquia de escopo (igual aos resources):

1. **Escopo de agent**: Herda de project + organization
2. **Escopo de project**: Herda da organization
3. **Escopo de organization**: Prompts do nível base

Ao ler um prompt, o sistema busca do escopo mais específico (agent) para o menos específico (organization).

## Formato do template de prompt

Templates de prompt normalmente incluem:
- **Instruções**: Orientação passo a passo
- **Contexto**: Informações de fundo necessárias
- **Exemplos**: Entradas/saídas de exemplo
- **Checklist**: Itens a verificar

Exemplo de estrutura de template de prompt:

```markdown
# Feature Development Workflow

## Instructions
1. Review the feature requirements
2. Design the implementation approach
3. Write tests first (TDD)
4. Implement the feature
5. Run all tests
6. Create pull request

## Context
- Follow the coding standards in coding-guidelines.md
- Ensure test coverage > 80%
- Document public APIs

## Checklist
- [ ] Tests written and passing
- [ ] Documentation updated
- [ ] No breaking changes
```
