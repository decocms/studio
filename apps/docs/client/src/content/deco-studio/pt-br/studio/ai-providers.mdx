## O que são AI providers?

**AI Providers** são os serviços de modelos de IA que alimentam o [Decopilot](/pt-br/studio/decopilot/overview) e seus agents. Você conecta um provider uma vez no nível da organização, e todos os seus agents passam a usá-lo a partir daí.

O Studio suporta múltiplos providers ao mesmo tempo — você pode combinar e alternar entre eles.

## Default models: uma escolha por propósito

Você não escolhe um model toda vez que inicia uma tarefa. Em vez disso, o Studio usa cinco **default models**, um para cada tipo de trabalho:

| Default | Para que serve | Escolha típica |
|---|---|---|
| **Fast** | Respostas rápidas, interações curtas | Claude Haiku, GPT-4 mini, Gemini Flash |
| **Smart** | Equilíbrio entre velocidade e capacidade — o default do dia a dia | Claude Sonnet, GPT-4o, Gemini Pro |
| **Thinking** | Raciocínio mais difícil, planejamento longo | Claude Opus, série o, Gemini Ultra |
| **Image** | Geração de imagens | GPT Image, Imagen, etc. |
| **Web research** | Busca na web e deep research | Sonar, Perplexity, etc. |

Configure isso uma vez em **Settings → AI Providers → Default models**. Quando um agent ou o Decopilot escolhe um tier, ele roteia para o model que você definiu. Mude um default e cada agent passa a usar o novo model imediatamente — sem reconfigurar agent por agent.

Você ainda pode sobrescrever isso por agent quando necessário, mas os defaults cobrem o caso comum.

## Deco AI Gateway

O **Deco AI Gateway** é o provider recomendado. Organizações novas começam com créditos — sem API keys para gerenciar — e ele dá acesso a mais de 100 models de diversos fornecedores por trás de uma única connection. Pague conforme usar.

Se quiser usar suas próprias keys mais tarde, adicione outro provider; o Studio usará o provider que você definir para cada tier de default model.

Você pode conferir o crédito restante do gateway e fazer recarga diretamente em **Settings → AI Providers**.

## Outros providers

Clique em **Connect provider** em **Settings → AI Providers** para adicionar qualquer um destes:

| Provider | Observações |
|---|---|
| **OpenRouter** | Uma conta, centenas de models de diversos fornecedores |
| **Anthropic** | API key direta da Anthropic — família Claude |
| **Google Gemini** | API key direta do Google AI Studio — família Gemini |
| **OpenAI-compatible** | Qualquer endpoint que fale a API OpenAI Chat Completions |

### Presets OpenAI-compatible

O provider **OpenAI-compatible** tem presets com marca para deployments comuns — escolha um e o Studio preenche a base URL automaticamente. Você também pode escolher **Custom** e colar qualquer URL.

| Preset | Para que serve |
|---|---|
| **OpenAI** | API key direta da OpenAI — GPT-4, GPT-5, etc. |
| **LiteLLM** | Um gateway LiteLLM gerenciado pelo seu time |
| **Ollama** | Models open-source rodando localmente via Ollama |
| **LM Studio** | Models abertos rodando através do LM Studio |
| **vLLM** | O servidor vLLM self-hosted do seu time |
| **Custom** | Qualquer outro endpoint compatível com OpenAI (avançado) |

### Providers somente locais

Quando o Studio roda localmente (via `bunx -p decocms deco`), dois providers extras aparecem, delegando a um CLI instalado na sua máquina:

| Provider | Observações |
|---|---|
| **Claude Code** | Conduz uma sessão do CLI `claude` — usa sua auth Anthropic existente |
| **Codex** | Conduz uma sessão do CLI `codex` |

Eles não aparecem no produto cloud.

## Sua assinatura Claude (use seu próprio plano)

Runs de coding hosted em sandbox (as tasks do Super Agent no Task Board, e outros fluxos que despacham um run `claude-code` para uma cloud sandbox) normalmente cobram do crédito de IA conectado da organização. Se você preferir pagar seus próprios runs de coding com seu plano pessoal **Claude Pro ou Max**, vincule-o em **Settings → AI Providers → Sua assinatura Claude**:

1. Na sua própria máquina, execute `claude setup-token` e copie o token exibido.
2. Cole o token no card **Sua assinatura Claude** e clique em **Link**.

Depois de vinculado, seus próprios runs usam o seu plano em vez do crédito da org — ele tem prioridade sobre o provider configurado no tier Thinking da org, especificamente para runs `claude-code` hosted em sandbox. Se a Anthropic invalidar o token (por exemplo, quando ele expira), o Studio faz fallback automático para a credencial da org em vez de falhar o run; o card mostra um estado de **expirado** para que você saiba que precisa gerar um novo token.

Clique em **Disconnect** para desvincular sua assinatura a qualquer momento.

<Callout type="info">
Isso afeta apenas runs `claude-code` hosted em sandbox. Não tem relação com o provider **Claude Code** somente local descrito acima, que conduz um CLI na sua própria máquina.
</Callout>

## Como um provider é conectado

**API key** — o método mais comum. Cole a key do dashboard do seu provider. Ela é armazenada criptografada e nunca exposta ao seu time.

**Sign in with browser** — para providers que suportam (Deco AI Gateway, OpenRouter). Você é levado à página de login do provider, autoriza o acesso e o Studio cuida do resto.

**Local endpoint** — para os presets Ollama, LM Studio, vLLM, LiteLLM ou Custom do OpenAI-compatible: cole a base URL onde o Studio consegue alcançar o servidor.

**CLI activate** — para Claude Code e Codex em modo local: o Studio roda o CLI instalado na sua máquina; nenhuma key é armazenada do lado do Studio.

## Quais models estão disponíveis?

Uma vez que um provider está conectado, você pode navegar pelos models disponíveis. Cada model mostra:

- Seu nome e capacidades (texto, visão, geração de imagem, etc.)
- Tamanho da janela de contexto
- Preço por token

A disponibilidade de models pode ser filtrada pelas configurações de permissão de model da sua organização. Se um model que você espera não aparece, verifique com o admin da sua org.

## Fallback

Se o provider por trás de um tier de default estiver indisponível, o Studio faz fallback para outro provider conectado automaticamente — então uma queda temporária em um fornecedor não quebra seus agents.
