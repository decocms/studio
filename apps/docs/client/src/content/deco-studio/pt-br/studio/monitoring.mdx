## Todas as tool calls em um só lugar

O Studio registra todas as invocações de tools que passam por ele — automaticamente, sem necessidade de configuração. Quando um agent consulta o GitHub, envia uma mensagem no Slack ou chama seu banco de dados, há um registro disso.

Você encontra tudo em **Settings → Monitor**. As tool calls de cada agent são consolidadas ali, em toda a organização.

<Callout type="tip">
**O que é registrado:** tool calls que passam pelas suas connections e agents (consultas ao GitHub, operações de banco de dados, chamadas ao Shopify, etc.). Ações de gerenciamento do Studio — como criar uma connection ou atualizar configurações — não são incluídas no log de monitoramento.
</Callout>

Sem um lugar central para isso, você teria que correlacionar logs de diferentes clients e diferentes serviços, cada um em um formato distinto — quando estivessem logando. O Studio captura tudo no ponto por onde todo o tráfego passa, então você sempre tem uma visão completa e consistente.

## O que você pode ver

Para cada tool call, o Studio registra:

**Quem fez a chamada**
- O usuário ou API key que fez a requisição
- De qual agent ou automação a chamada veio

**O que aconteceu**
- A tool que foi chamada
- Os inputs que foram enviados
- O output retornado
- Se teve sucesso ou falhou — e, se falhou, por quê

**Quando e por quanto tempo**
- Timestamp
- Quanto tempo a chamada levou, em milissegundos

## O que você pode fazer com isso

### Debugar falhas rapidamente

Quando algo quebra, abra **Settings → Monitor** e veja exatamente o que aconteceu — quais inputs foram enviados, qual erro retornou, quando ocorreu. Sem SSH, sem arquivos de log, sem adivinhação.

### Acompanhar performance

Veja quais tools são mais lentas (latência p50 / p95), quais são chamadas com mais frequência e onde o tempo está sendo gasto. Isso facilita identificar gargalos antes que se tornem problemas.

### Entender como seu time usa os agents

Veja quais tools estão de fato sendo usadas versus as que estão apenas configuradas. Identifique onde os agents estão fazendo retry ou encontrando erros com frequência. Use isso para melhorar seus agents ao longo do tempo.

### Auditar acessos

Cada tool call está vinculada a um usuário ou API key específicos. Se você precisa saber quem acessou o quê e quando — para compliance, revisão de segurança ou resposta a incidentes — está tudo lá.

## Uma observação sobre dados sensíveis

Os inputs e outputs das tools são logados por padrão. Se você trabalha com dados sensíveis (registros de clientes, dados financeiros, etc.), use API keys com escopo para limitar o que cada agent pode acessar e revise as configurações de retenção de dados da sua organização.

O Studio fornece a visibilidade — seu time define as políticas.
