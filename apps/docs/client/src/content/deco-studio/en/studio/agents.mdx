## What are agents?

**Agents** are AI configurations built for a specific job. While [projects](/en/studio/projects) give your team a broad workspace, agents focus narrowly — one purpose, one set of tools, one job done well.

An agent has:

- **A clear goal** — what it does and when to use it
- **The right tools** — only what it needs, nothing it doesn't
- **Detailed instructions** — how to behave, what to prioritize, what to avoid
- **Resources and templates** — any extra context it needs to do the job

Agents live in the sidebar under **Agents** and can be started in any context — tasks, projects, or conversations — with a fresh slate each time.

## How agents work

When decopilot needs help with a specific task, it reads each agent's description to decide which one to start. A well-written description is what makes an agent discoverable and useful.

Write descriptions that clearly state the job:
- "Process customer refunds and authorize returns"
- "Analyze inventory levels and flag restock alerts"
- "Generate and send weekly performance reports"

The instructions field is where you go deeper — step-by-step guidance, constraints, fallback behavior, and anything the agent should always or never do.

## Example: order fulfillment agent

An order fulfillment agent might combine Shopify tools for order management, ShipStation tools for shipping labels, and Slack tools for team notifications. Its job is to handle one end-to-end workflow — fetch pending orders, check inventory, generate labels, send tracking updates — without touching anything outside that scope.

## Built-in agents

Studio ships with agents for managing the platform itself:

- **Agent management** — create, edit, and remove agents
- **Connection management** — add and configure integrations
- **Permission management** — control who can access what
- **MCP Store** — browse and install tools from the store
- **User management** — invite and manage organization members

These are ready to use immediately, without any setup.

## Designing a good agent

**Keep the scope tight.** An agent that does one thing well is more reliable and easier to maintain than one that tries to do everything. If you find yourself adding unrelated tools, consider making a second agent.

**Write instructions like you're handing off to someone new.** Include the workflow steps, any edge cases they should watch for, and what to do when something goes wrong.

**Choose tools deliberately.** A customer service agent needs order lookup and refund tools — not inventory or marketing tools. The fewer unrelated tools, the more focused the agent's behavior.

**Good**: "Order Fulfillment Agent" — processes and ships orders

**Too broad**: "Ecommerce Operations Agent" — fulfillment, customer service, inventory, marketing, analytics...

## Ways to use agents

- **Started by decopilot** — agents are launched automatically when relevant to the current task
- **Built-in agents** — pre-configured and ready for platform management tasks
- **Custom agents** — built by your team for your specific workflows

When you're working inside an agent, you'll only see its tools and resources — nothing else. That's intentional. The focused view helps you stay on task.
