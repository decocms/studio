## What is the Agentic CMS?

The **Agentic CMS** is the next generation of [deco.cx](https://docs.deco.cx) — a visual CMS for storefronts and content-heavy digital experiences, built on top of [deco Studio](/en/studio/overview). It's the flagship of deco's [Digital Experience suite](/en/studio/digital-experience).

It's two things in one:

- **A CMS** — type-safe React components, TypeScript loaders, theme editor, Git-based versioning, real-time collaboration between developers and content teams. The same model deco.cx established, refined.
- **A team of agents** — focused AI workers that author content, adjust the design, enrich the catalog, and keep the site healthy. They work alongside your team and you stay in control.

## Who it's for

Teams managing **storefronts** (ecommerce, marketplaces) and **content-driven sites** (media, branded D2C, knowledge bases) who want:

- The collaboration and performance of a code-first stack
- The speed and reach of a visual editor
- AI agents that scale the operational work — without hiding what they're doing

It replaces the boundary between "the engineering team that maintains the site" and "the content team that fills it." Both work in the same product, with agents handling the toil in between.

## Git-native, by design

Every change to your site — whether a person made it from the visual editor or an agent made it from chat — flows through the same Git workflow you already know:

1. The change is committed to a branch
2. A pull request is opened with a diff your team can review
3. Reviewers approve or request changes
4. On merge, the change ships to your site

This is the same model deco.cx pioneered, and it carries over directly. **Agents don't bypass review.** They open PRs like anyone else, and your team stays the source of truth — your repo, your branches, your history. Roll back, audit, and trace any change to its author, human or agent.

## How it relates to deco.cx

If you're coming from deco.cx, the Agentic CMS is the same product line — same core concepts (sections, loaders, blocks, theme editor, Decopilot), now plugged into Studio so your storefront ships with a full agent control plane around it.

| deco.cx concept | Agentic CMS today |
|---|---|
| Sections (React/TS components) | Same, with optional agent-authored variants |
| Loaders (data fetching) | Same, now visible as tools to your agents |
| Blocks (reusable units) | Same |
| Theme Editor | Same |
| Decopilot | Promoted to a first-class assistant scoped to your site |
| Admin UI | Now part of the Studio agent shell |
| Git workflow | Same — every change goes through PR review |

Existing deco.cx projects continue to work. Migration adds the agent layer; it doesn't replace your codebase.

## Next-major Blocks sites

Sites built on next-major Blocks are edited through the **content protocol**: the site editor reads the committed schema (`.deco/schema.gen.json`, or `.deco/meta.gen.json`) and the saved blocks in `.deco/blocks`, and never runs the site's code. This is behind the `site_editor_content_protocol` organization flag, off by default.

With the flag on, a project uses the protocol when:

- **A Fast Preview session's branch has a committed schema.** Each save is one commit on the draft branch, the schema comes from that branch (or the default branch when it has none), and the preview renders your site with a `?__draft=` link.
- **It's connected to `deco serve` on your machine.** Run `npx @decocms/blocks serve` next to your dev server and open the site editor link it prints. Studio only accepts links to a server on your machine (`localhost` or `127.0.0.1`) and asks which project to connect; Chrome asks once whether Studio may reach a server on your machine. Saves write the files in your working tree and uploads go to `public/assets/`, and you commit them yourself. The site editor shows a **Local server** chip with **Disconnect**, and asks you to reconnect when the server restarts with a new token.

Everything else, including sessions with a sandbox, stays on the existing editing path.

Because the site's code never runs:

- The preview opens the real app; nothing is re-rendered in place, and the add-section gallery shows each block's name, description and schema image.
- Pickers whose options come from a loader show the schema's options, otherwise a text field.
- Secret fields are write-only: Studio encrypts what you type in the browser with the site's public key, `.deco/secrets.pub`, and saves only the ciphertext. Secrets saved by older sites can't be edited here.
- Running loaders and actions and installing apps aren't available: they live in the site's code.

## Getting started

Open Studio, find the **deco Site Editor** agent and point it at your site.
