## What are connections?

**Connections** are the tools and services you've plugged into Studio — GitHub, Slack, a database, your own API, or any other MCP-compatible service.

You set up a connection once. From then on, your whole team can use it across agents and projects, without anyone touching credentials.

## Why connections exist

Without a centralized place for tools, every person and every AI client has to manage its own credentials. Rotate a password? Update it in ten places. Revoke someone's access? Hope they're not using a hardcoded key somewhere.

Connections solve this by being the single source of truth:

- **Credentials stored once** — encrypted at rest, decrypted only when a tool is called
- **Shared across your team** — anyone with access can use the tool without seeing the credentials
- **Easy to update** — change credentials in one place, every client picks it up automatically
- **Easy to revoke** — remove a connection and nobody can use it, immediately
- **Fully logged** — every tool call is recorded with who made it, when, inputs, and outputs

## Types of connections

**SaaS apps** — GitHub, Slack, Notion, Google Drive, and similar services. Most connect with one-click OAuth, so you never copy a token.

**Infrastructure** — Databases, cloud APIs, internal services. You configure the endpoint and credentials, Studio handles the rest.

**Custom tools** — Your own MCP server exposing domain-specific operations. Plug it in and share it with your team like any other connection.

All connection types work the same way: configure once, use anywhere through agents and projects.

## How a tool call works

When an agent calls a tool through a connection:

1. The agent authenticates to Studio
2. Studio checks that it has permission to use that tool
3. Studio retrieves the stored credentials for that connection
4. Studio sends the request to the external service
5. Studio logs the call (tool, timing, inputs, outputs, status)
6. Studio returns the result to the agent

The external service never sees your agent directly — only Studio. Your credentials never leave Studio's secure boundary.

```
GitHub Connection  ──┐
Slack Connection   ──┼──▶ Project or Agent ──▶ Your team
Database Connection──┘
```

## Connecting AI clients to Studio

Once you've set up connections, you can point AI clients (Claude Desktop, Cursor, custom agents) at Studio to use them.

- **For interactive clients** — use OAuth, which handles sign-in and per-user identity
- **For automation and server-to-server** — use API keys, which are faster to set up and ideal for scripts or background agents

<Callout type="tip">
  If you want a single endpoint that exposes a curated set of tools, set up an **Agent**. If you need direct access to one specific connection, use the connection proxy URL.
</Callout>

<Callout type="info">
  Connections are the foundation for [Virtual MCPs](/en/studio/virtual-mcps), [Projects](/en/studio/projects), and [Agents](/en/studio/agents). You connect individual tools first, then compose them into higher-level workspaces.
</Callout>
