Every AI model has a limit on how much it can hold in memory at once — your instructions, the tools available, and the full conversation history all count toward that limit. The more you've discussed in a conversation, the more memory it takes up.

Decopilot manages this automatically, but understanding how it works helps you get more done in a single session.

## How memory fills up

When decopilot starts a task, it loads:

- Its core instructions and behavior
- Guidelines from your current scope (org, project, or agent)
- The tools available in that scope
- Your conversation history so far

As the conversation grows, the history takes up more space. When it gets too full, decopilot automatically summarizes the older parts of the conversation and keeps the summary instead. This frees up space to continue working without losing the important context.

## The 40/80 rule

- **Below 40% full** — plenty of room, no action needed
- **40–80% full** — still working fine, but worth wrapping up the current phase
- **Above 80% full** — decopilot automatically summarizes the conversation history to free up space

You can also trigger this manually with the `/compact` command — useful before starting a new phase of complex work.

<Callout type="tip">
Use `/compact` when you're finishing one major task and starting another. It keeps the conversation lean without losing what matters.
</Callout>

## Using subtasks to stay focused

The most effective way to manage memory is to keep heavy work in [subtasks](/en/studio/decopilot/tasks-and-spawning). A subtask starts with a clean slate, does the work, and returns only a short summary to your main conversation.

**Without subtasks:**
```
Main conversation fills up with research details,
calculations, and verbose tool outputs → hits memory
limit faster
```

**With subtasks:**
```
You: "Research Q4 demand trends"
  ↓
Subtask runs with clean memory, analyzes data
  ↓
Returns: "Top 3 SKUs to reorder, suggested quantities..."
  ↓
Main conversation: only sees the summary
```

You can also use a specialist [agent](/en/studio/agents) inside a subtask to bring domain expertise without cluttering your main conversation.

## How scopes affect memory

When you switch scopes — from org to a project, or into an agent — the tools and guidelines that load into memory change. A project scope loads that project's tools and instructions on top of the org-level ones. An agent scope loads the agent's specific toolset and instructions.

See [Scopes](/en/studio/decopilot/scopes) for details.

## Practical tips

**Watch the usage indicator** — when you're approaching 40%, think about wrapping up the current phase or using `/compact`.

**Use subtasks for heavy work** — research, data analysis, code reviews, and anything that generates long outputs should happen in subtasks. Keep summaries in your main conversation.

**Be selective with tools** — decopilot loads tools into memory. Don't enable tools you don't need for the current task.

**Work in phases** — finish one thing, compact or start a subtask for the next. Keeping each phase focused makes the whole session more productive.
