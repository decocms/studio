## Two types of tools

Decopilot has access to two types of tools:

**Built-in tools** — always available, used for managing work, delegating tasks, and reading context. These are the same regardless of which scope you're in.

**Scope tools** — come from the connections in your current scope. If you're in a project with Shopify and ShipStation connected, you'll have access to tools like `GET_ORDERS`, `CREATE_SHIPPING_LABEL`, and so on.

---

## Built-in tools

| Tool | Available in subtasks | What it does |
|---|:---:|---|
| `agent_search` | Yes | Find agents in your organization |
| `subtask` | No | Start a subtask, optionally with a specific agent |
| `user_ask` | No | Ask you a question when it needs input |
| `sandbox` | Yes | Run JavaScript code with access to your tools |
| `read_resource` | Yes | Read documentation or guidelines from the current scope |
| `read_prompt` | Yes | Read a reusable prompt template |
| `read_tool_output` | Yes | Filter a large tool result to find what's relevant |
| `propose_plan` | No | Propose a plan for your approval before acting |

Subtasks have restricted access — they can't start additional subtasks or ask you questions, since they're meant to run and report back without interruption.

---

## Scope tools

Scope tools are the domain-specific capabilities tied to your current context — Shopify tools if you're in a Shopify project, shipping tools if you have a ShipStation connection, and so on.

**Example**: A project with Shopify and ShipStation might expose:
- `GET_ORDERS` — fetch customer orders
- `UPDATE_INVENTORY` — update stock levels
- `CREATE_SHIPPING_LABEL` — generate shipping labels
- `GET_PRODUCTS` — list the product catalog

Which tools are available depends on what connections are configured in the current scope's Virtual MCP.

---

## How decopilot uses tools

Decopilot starts each task with only its built-in tools. It sees the scope tools listed in its instructions and uses them as needed to complete your request.

For complex work, it can delegate to a subtask (using `subtask`) or load additional context first (using `read_resource` or `read_prompt`) before acting.
