## What are tasks?

A **task** is your conversation with decopilot — where you chat, decopilot uses tools, and work gets done. Tasks are accessible from the homepage chat interface, the sidebar panel, and your task history.

Every task runs within a [scope](/en/studio/decopilot/scopes) (organization, project, or agent) that determines what instructions and tools are available. You can switch scopes anytime using the button at the bottom of the chat input.

## Task states

Every task has one of four states:

- **In progress** — the agent is working or waiting for your next message
- **Requires action** — paused, waiting for your input (a tool needs approval, or the agent asked you a question)
- **Completed** — work finished successfully
- **Failed** — something went wrong, or the task timed out

You can see tasks that need your attention by clicking the **tasks icon** in the sidebar.

Tasks time out after **30 minutes of inactivity**. If you're working on something longer, just send a message periodically to keep it active.

## What are subtasks?

A **subtask** is a separate conversation that branches off from your main task to handle focused work. The key difference: it starts with a clean slate — no history from your main conversation.

This is useful when a piece of work would generate a lot of back-and-forth that you don't need to see. The subtask runs, does the work, and returns only a short summary to your main conversation. The full details are saved in task history if you need them later.

Subtasks can't ask you questions and can't create additional subtasks — they run autonomously and report back.

### Main task vs. subtask

| | Main task | Subtask |
|---|---|---|
| Conversation history | Accumulates over time | Starts fresh |
| Can ask you questions | Yes | No |
| Can create subtasks | Yes | No |
| Returns to parent | N/A | Summary only |

## When subtasks help

**Research and analysis** — send a subtask to dig into data, explore options, or investigate an issue. You get back the conclusion, not every step along the way.

**Complex calculations** — anything that generates verbose output belongs in a subtask. You see the result, not the working.

**Quality checks** — audits, validation, reviews. Run them separately and get back a summary of what was found.

**Parallel work** — if two pieces of work don't depend on each other, run them as separate subtasks at the same time instead of one after the other.

**Example**: Planning inventory purchases — start a subtask to research sales trends and seasonal patterns. Your main conversation receives the recommendation without being filled with raw data.

## Using specialist agents in subtasks

You can run a subtask using a specific [agent](/en/studio/agents) — one that's been configured for a particular domain. The agent brings its own focused toolset and instructions, without affecting your main conversation.

**Example**: Your main task is coordinating an order fulfillment workflow. You start subtasks using:
- An **Inventory Agent** to check stock availability
- A **Shipping Agent** to plan logistics
- A **Customer Service Agent** to prepare support notes

Each one works independently. Your main task gets the summaries and coordinates the outcome.

---

## Practical tips

**Offload heavy work** — research, calculations, and audits should happen in subtasks. Keep results in your main task, not the details.

**Run things in parallel** — if two subtasks don't depend on each other, start them at the same time.

**Write clear prompts** — "Analyze Q4 apparel demand trends" is more useful than "Do analysis" when reviewing task history later.

**Check history when needed** — the full subtask conversation is saved. Open it from history if you need the details behind the summary.
