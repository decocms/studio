## What are projects?

**Projects** are shared workspaces that bring agents, tools, and context together around a specific goal or team.

Think of a project like an office for a particular initiative — it has the right tools on the desk, the right guidelines on the wall, and access only for the people who need it. Work happening in one project doesn't bleed into another.

Projects give you:

- **Organization** — group capabilities by product line, client, or team
- **Isolation** — each project has its own tools and credentials, separate from everything else
- **Context** — project-specific instructions, documentation, and workflow templates
- **Clear ownership** — match your technical setup to how your team actually works

## Setting up a project

When you create a project, you configure:

1. **Name and description** — what this project is for, so your team knows at a glance
2. **Instructions** — guidelines for how AI agents should behave in this project (tone, constraints, priorities)
3. **Tools** — the actions agents can take, selected from your [connections](/en/studio/connections) or defined inline
4. **Resources** — extra context agents should know about (documentation, brand guidelines, domain knowledge)
5. **Prompts** — reusable workflow templates for the most common tasks in this project

## Example: multi-brand storefront

A storefront project might include Shopify tools for catalog management, Stripe tools for payments, and analytics tools for tracking performance. Brand-specific guidelines live in resources. Agents working in this project manage listings, process orders, and follow brand standards — all within the project's isolated scope.

If you run multiple brands, each gets its own project: isolated credentials, separate configurations, no cross-contamination.

## Isolation by design

When an agent connects to a project, it only sees what's in that project — the tools, resources, and prompts you configured. It can't access tools or credentials from another project.

This makes it safe to run separate initiatives in parallel without worrying about agents crossing boundaries.

## Common use cases

- **Multiple clients or brands** — one project per client, with isolated credentials and configurations
- **Separate teams** — sales, engineering, and support each get their own workspace
- **Seasonal campaigns** — temporary projects with the tools needed for a specific push
- **Regulated workflows** — keep sensitive operations isolated from general-purpose work
