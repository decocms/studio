Este guia mostra como executar o Studio com Docker Compose para avaliação local
e self-hosting.

Código-fonte: [decocms/studio → deploy/docker-compose](https://github.com/decocms/studio/tree/main/deploy/docker-compose)

<Callout type="tip">
  Este é o guia curto mantido na rota legada da documentação. Veja a
  [referência canônica de Docker Compose](/pt-br/studio/self-hosting/deploy/docker-compose)
  para autenticação, operações, upgrades e troubleshooting.
</Callout>

## Escolha um arquivo Compose

O repositório fornece três configurações:

- `docker-compose.postgres.yml` — Studio com PostgreSQL, NATS e MinIO. É a
  configuração all-in-one recomendada para self-hosting.
- `docker-compose.yml` — apenas o Studio, conectado a um banco PostgreSQL
  fornecido por você.
- `docker-compose.dev.yml` — PostgreSQL e um cluster NATS com três nós para
  desenvolver os apps de API e web a partir do código-fonte.

## Início rápido

```bash
git clone https://github.com/decocms/studio.git
cd studio/deploy/docker-compose

cat > .env << EOF
BETTER_AUTH_SECRET=$(openssl rand -base64 32)
ENCRYPTION_KEY=$(openssl rand -base64 32)
POSTGRES_USER=studio_user
POSTGRES_PASSWORD=$(openssl rand -base64 24)
POSTGRES_DB=studio_db
EOF

docker compose -f docker-compose.postgres.yml up -d
```

Abra `http://localhost:3000`.

A imagem publicada é
`ghcr.io/decocms/studio/studio:${IMAGE_TAG:-latest}`. O serviço Compose se chama
`studio`; os dados da aplicação usam o volume `studio-data`.

## Use seu próprio PostgreSQL

Defina as URLs públicas, os secrets e a conexão do banco em `.env`:

```bash
BETTER_AUTH_SECRET=seu_secret_gerado
ENCRYPTION_KEY=sua_chave_de_criptografia_estavel
BASE_URL=https://studio.example.com
BETTER_AUTH_URL=https://studio.example.com
DATABASE_URL=postgresql://usuario:senha@database.example.com:5432/studio
```

Depois, inicie a configuração base:

```bash
docker compose up -d
```

<Callout type="warning">
  Mantenha `BETTER_AUTH_SECRET` e `ENCRYPTION_KEY` estáveis entre reinicializações.
  Em produção, armazene os valores em um gerenciador de secrets em vez de
  fazer commit deles.
</Callout>

## Configuração de autenticação

Para SAML/SSO, providers de e-mail ou outras configurações avançadas de
autenticação, monte um `auth-config.json` em
`/app/apps/api/auth-config.json`. Use
[`apps/api/auth-config.example.json`](https://github.com/decocms/studio/blob/main/apps/api/auth-config.example.json)
como ponto de partida.

## Operações

```bash
# Acompanhar logs da aplicação
docker compose logs -f studio

# Reiniciar apenas o Studio
docker compose restart studio

# Atualizar a imagem e recriar o serviço
docker compose pull studio
docker compose up -d --force-recreate studio

# Parar a stack sem apagar volumes
docker compose down
```

Use `docker compose down -v` somente quando quiser remover intencionalmente os
dados locais persistentes.
