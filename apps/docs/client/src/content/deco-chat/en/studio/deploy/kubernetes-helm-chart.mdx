This guide gives the shortest supported path to a Studio deployment on
Kubernetes.

Chart sources:

- [Studio](https://github.com/decocms/studio/tree/main/deploy/helm/studio)
- [Sandbox operator](https://github.com/decocms/studio/tree/main/deploy/helm/sandbox-operator)
- [Sandbox environment](https://github.com/decocms/studio/tree/main/deploy/helm/sandbox-env)

<Callout type="tip">
  This is the short guide kept at the legacy documentation route. Use the
  canonical [Kubernetes reference](/en/studio/self-hosting/deploy/kubernetes)

## Deployment model

A complete hosted-agent deployment has three releases:

| Chart | Scope | Purpose |
| --- | --- | --- |
| `chart-deco-studio` | Per Studio environment | nginx front door, API containers, queue workers, NATS, and optional observability |
| `sandbox-operator` | Per cluster | Kubernetes SIGs agent-sandbox controller and CRDs |
| `sandbox-env` | Per Studio environment | Sandbox template, RBAC, sentinel Secret, and optional warm pool and preview Gateway |

The current API/worker topology requires PostgreSQL. Hosted sandboxes also
require S3-compatible object storage.

## Install

Pin the chart versions used by this checkout:

```bash
export STUDIO_CHART_VERSION=0.12.4
export SANDBOX_OPERATOR_CHART_VERSION=0.1.3
export SANDBOX_ENV_CHART_VERSION=0.9.13
```

### 1. Install the sandbox operator

```bash
helm install sandbox-operator \
  oci://ghcr.io/decocms/studio/charts/sandbox-operator \
  --version "$SANDBOX_OPERATOR_CHART_VERSION" \
  --namespace agent-sandbox-system \
  --create-namespace
```

### 2. Configure and install Studio

Create a stable Kubernetes Secret in the `deco-studio` namespace containing
`DATABASE_URL`, `BETTER_AUTH_SECRET`, `ENCRYPTION_KEY`, `S3_ENDPOINT`,
`S3_BUCKET`, `S3_ACCESS_KEY_ID`, and `S3_SECRET_ACCESS_KEY`.

Create `studio-values.yaml`:

```yaml
database:
  engine: postgresql
  url: "" # supplied as DATABASE_URL by the existing Secret

serviceAccount:
  create: true
  name: deco-studio
  automount: true

configMap:
  meshConfig:
    BETTER_AUTH_URL: "https://studio.example.com"
    BASE_URL: "https://studio.example.com"
    STUDIO_AGENT_SANDBOX_ENABLED: "true"
    STUDIO_ENV: "production"
    STUDIO_SANDBOX_TEMPLATE_NAME: "studio-sandbox-production"

secret:
  secretName: deco-studio-secrets
```

<Callout type="note">
  `configMap.meshConfig` is a deprecated chart-key name retained for upgrade
  compatibility. Its values configure the Studio API. Do not put credentials
  there; keep them in the Secret.
</Callout>

Install the application chart:

```bash
helm install deco-studio \
  oci://ghcr.io/decocms/chart-deco-studio \
  --version "$STUDIO_CHART_VERSION" \
  --namespace deco-studio \
  --create-namespace \
  --values studio-values.yaml
```

The main Deployment contains nginx and two API containers. A separate worker
Deployment is required and enabled by default.

### 3. Install the environment's sandbox resources

```bash
helm install sandbox-env-production \
  oci://ghcr.io/decocms/studio/charts/sandbox-env \
  --version "$SANDBOX_ENV_CHART_VERSION" \
  --namespace agent-sandbox-system \
  --set envName=production \
  --set mesh.namespace=deco-studio \
  --set mesh.serviceAccountName=deco-studio
```

<Callout type="note">
  The sandbox chart's `mesh.*` values key is also a deprecated name retained
  for compatibility; it points to the Studio release. `mesh.serviceName`,
  `mesh.servicePort`, and `mesh.podSelectorLabels` are deprecated and unused.
</Callout>

## Verify

```bash
helm status deco-studio -n deco-studio
helm status sandbox-operator -n agent-sandbox-system
helm status sandbox-env-production -n agent-sandbox-system

kubectl get deployments,pods -n deco-studio
kubectl get sandboxtemplate,sandboxwarmpool -n agent-sandbox-system
kubectl port-forward svc/deco-studio 8080:80 -n deco-studio
```

Studio is then available at `http://localhost:8080`.
