This guide covers running Studio with Docker Compose for local evaluation and
self-hosting.

Source: [decocms/studio → deploy/docker-compose](https://github.com/decocms/studio/tree/main/deploy/docker-compose)

<Callout type="tip">
  This is the short guide kept at the legacy documentation route. See the
  canonical [Docker Compose reference](/en/studio/self-hosting/deploy/docker-compose)
  for authentication, operations, upgrades, and troubleshooting.
</Callout>

## Choose a Compose file

The repository provides three configurations:

- `docker-compose.postgres.yml` — Studio with PostgreSQL, NATS, and MinIO. This
  is the recommended all-in-one self-hosted setup.
- `docker-compose.yml` — Studio only, connected to a PostgreSQL database that
  you provide.
- `docker-compose.dev.yml` — PostgreSQL and a three-node NATS cluster for
  developing the API and web apps from source.

## Quick start

```bash
git clone https://github.com/decocms/studio.git
cd studio/deploy/docker-compose

cat > .env << EOF
BETTER_AUTH_SECRET=$(openssl rand -base64 32)
ENCRYPTION_KEY=$(openssl rand -base64 32)
POSTGRES_USER=studio_user
POSTGRES_PASSWORD=$(openssl rand -base64 24)
POSTGRES_DB=studio_db
EOF

docker compose -f docker-compose.postgres.yml up -d
```

Open `http://localhost:3000`.

The published image is
`ghcr.io/decocms/studio/studio:${IMAGE_TAG:-latest}`. The Compose service is
named `studio`; application data uses the `studio-data` volume.

## Bring your own PostgreSQL

Set the public URLs, secrets, and database connection in `.env`:

```bash
BETTER_AUTH_SECRET=your_generated_secret
ENCRYPTION_KEY=your_stable_encryption_key
BASE_URL=https://studio.example.com
BETTER_AUTH_URL=https://studio.example.com
DATABASE_URL=postgresql://user:password@database.example.com:5432/studio
```

Then start the base configuration:

```bash
docker compose up -d
```

<Callout type="warning">
  Keep `BETTER_AUTH_SECRET` and `ENCRYPTION_KEY` stable across restarts. Store
  production values in a secret manager rather than committing them.
</Callout>

## Authentication configuration

For SAML/SSO, email providers, or other advanced authentication settings, mount
an `auth-config.json` at `/app/apps/api/auth-config.json`. Start from
[`apps/api/auth-config.example.json`](https://github.com/decocms/studio/blob/main/apps/api/auth-config.example.json).

## Operations

```bash
# Follow application logs
docker compose logs -f studio

# Restart only Studio
docker compose restart studio

# Update the image and recreate the service
docker compose pull studio
docker compose up -d --force-recreate studio

# Stop the stack without deleting volumes
docker compose down
```

Use `docker compose down -v` only when you intentionally want to remove
persistent local data.
